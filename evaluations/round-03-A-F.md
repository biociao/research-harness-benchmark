# 二、逐组详细评审

## 🥇 C：综合最强，最接近“可交付科研项目”

### C01 — Tyson 2004

这是 Tyson 复现中我认为**最成熟的一份**。

它不只是说“复现成功”，而是把数据、工件和脚本组织成了明确的 provenance 链：

- AADL01 组装；
- SRR9434122–25 原始 reads；
- binning；
- nif 检索；
- SNP rate；
- abundance；
- reference recovery；
- 最终报告。

报告还明确给出了脚本入口链：`map_reads.sh → binning_final.py → genes_and_markers.sh → snp_rates.py → table1_and_abundance.py → ref_recovery.py`。

更重要的是，它没有把“现代数据重新计算出来的数值”机械地冒充成论文原值，而解释了 **2.4× read depth、depth 定义、比对方式**造成的偏差。例如 LpII 多态率 0.58% 与论文 0.08%，FpII 为 4.04% 与论文 2.2%，同时给出原因。

**扣分点：**

- 部分代谢功能没有真正独立验证，而是引用补充注释；
- 某些结果与原论文无法做到逐数值一致；
- 报告很强，但完整的“从零一键部署”证据还没有达到 10 分级的全部要求。

**评分：9.4/10**

------

### C02 — Auton 2015

C02 的最大优点是**把复现变成 claim-level verification**，而不是泛泛地重新跑 PCA/Fst。

尤其是：

- 明确使用 chr21 v5b；
- 2,504 个体 / 26 人群 / 5 超级人群；
- 明确 ARI；
- 明确 Fst；
- 明确 variant counts；
- 明确环境锁定；
- 有 `run_all.sh`；
- 有 md5 / SHA-256；
- 有 30–60 分钟单机重跑说明。

其 Fst 实现还和 vcftools 做了逐位交叉验证：相同变体集下两者都是 **0.02388，n=7,335**。

这是非常好的科研 Agent 行为：**不是只验证自己的代码，而是寻找独立实现进行 oracle-style validation。**

**扣分点：**

- 依然只用 chr21 作为核心计算对象；
- 对全基因组 26×26 Fst 没有真正重跑；
- SI Table 5 OCR 存在问题，因此某些论文数值只能做弱参考。

**评分：9.2/10**

### C 综合：**9.3/10**

# 🥈 A：科学推理能力非常强

## A01 — Tyson 2004

A01 的优势非常明显：它不仅完成了复现，而且发现了**数据沉积与论文原始 assembly 不一致**这一重要问题。

报告明确指出：

> 当前 GenBank 沉积组装与论文 scaffold 集不一致，需要以 reads 重组装。

并且给出了独立 SPAdes assembly：

- 1,061 scaffolds；
- 9.39 Mb；
- 84.9% reads 利用；
- 5 个基因组均得到近完整恢复；
- 覆盖度 83–96%。

同时还复现了：

- GC + coverage binning；
- LpII vs FpII 多态性；
- FpII 嵌合结构；
- nif；
- RuBisCO/CODH；
- 纤维素合酶；
- 鞭毛；
- 金属抗性等。

特别值得肯定的是，它主动披露：

- trim-15 的近似实现；
- LpII 多态率约 0.198% vs 原文 0.08%；
- 重组窗口从 10 kb 改成 500 bp；
- 因而不能把数值直接当作完全一致。

这属于**高质量的复现逻辑，而不是“结果对上了就算成功”。**

**评分：9.1/10**

## A02 — 1000 Genomes

A02 是 1000G 复现里非常强的一份。

它报告：

- singleton 与 Table 1 差异 ≤3%；
- PCA **ARI=0.905 ≥0.9**；
- Fst 人群矩阵与论文 SI Table 5 相关性 **0.997**；
- 同时披露绝对尺度存在差异。

而且工程结构相当完整：

```
data/raw → data/derived → data/paper → code → experiments/E01–E05 → results → manuscript → artifacts → envs → reviews
```

并有环境锁定、execution log、artifact hash。

**不足：**

最大的科学问题是：**部分 claim 的“论文全基因组结果”被压缩成 chr21 验证。**

因此，“5 项全部复现”这个表述略显积极，严格来说更应该说：

> 五项核心论断在给定 chr21 数据范围内获得支持。

不过它已经把这个限制写出来了，因此属于**表述尺度问题，而不是严重逻辑错误**。

**评分：9.0/10**

# 四、最重要的横向发现

## 1. 真正拉开差距的不是“会不会写报告”，而是能否建立证据闭环

C/D/A 的共同特点是：

> **论文 claim → 原始数据 → 代码 → 中间结果 → 独立验证 → 最终结论 → 局限**

例如 C02 不仅算 Fst，还拿 vcftools 做独立交叉验证；E02 甚至记录 bug 修复后重新运行。

这比单纯报告“复现成功”高一个层级。

------

## 2. “发现复现失败”反而是高分行为

几个很值得肯定的例子：

- B02：ARI 只有 0.87，没有强行改成 PASS；
- F02：5 个 claim 中 4 个支持、1 个 inconclusive；
- F01：SNP/重组分析直接标记为未复现；
- A01：明确承认多态率和原文存在约 2 倍方法学差异；
- D01：指出论文 nif 归属后来发生科学修正。

这完全符合五维框架中“逻辑严密、避免无证据幻觉”的要求。

------

## 3. 最大共同问题：把“chr21 复现”写成“全基因组复现”

这是我认为这批附件中**最需要在最终评审里强调的问题**。

A02/B02/D02/E02/F02 等 1000G 任务实际上大量使用 **chr21**：

- C4 PCA；
- burden；
- Fst；
- 部分 variant count。

但原论文对应的是更大范围、甚至全基因组/26×26 population analysis。

例如 B02 自己已经承认：

> Fst 是 chr21 的 5×5，而论文是全染色体 26×26。

所以正式评审时最好把：

**“claim supported”**

和

**“paper-level exact reproduction”**

严格区分。

这也是为什么我没有给任何一个 Agent 的 1000G 单项任务直接打满分。

------

# 五、最终推荐

如果你的目的是**选出最值得作为科研 Agent 使用/继续训练的系统**：

### 第一梯队：**C ≈ A ≈ D**

**C**：最适合做真正的**科研复现工程**。
优势是 artifact、provenance、代码、交叉验证最完整。

**A**：最适合做**科学分析与异常发现**。
特别擅长识别数据沉积、方法差异和结果偏差。

**D**：最适合做**深度生物信息学研究任务**。
Tyson 2004 的分析深度尤其突出。

### 第二梯队：**F**

科研诚信和局限披露很好，但工程产品化程度略低。

### 第三梯队：**B**

科学理解没有明显问题，但代码和工程证据链还可以明显加强。

### 第四梯队：**E**

任务完成能力合格，1000G 版本其实很好；但 Tyson E01 的报告过于“结果仪表盘化”，深度不足，因此综合被拉低。

------

## 一句话结论

**如果按“科研 Agent 能否真正承担端到端可复现研究”而不是“报告写得是否漂亮”来评，推荐顺序是：**

> **C > A ≈ D > F > B > E**

其中 **C 是最均衡的工程型冠军，A 是推理型冠军，D 是深度科研型冠军**。

这套评分与五维框架中对“代码执行准确性、核心结果复现、工程规范、可视化合理性和端到端任务成功率”的要求是一致的。

如果用于正式评审，我建议**不要只提交总分**，而应把“**科学正确性 / 复现完整性 / 工程可重复性 / 证据诚实性**”四项作为最终淘汰项；其中“把 chr21 结果表述成全基因组复现”应作为重点扣分项。
